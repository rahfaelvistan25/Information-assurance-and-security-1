LESSON 2: Threat Modeling and Cybersecurity Threats

Think like an adversary to proactively defend your infrastructure. Master modern cybersecurity threat classifications, the 6-step threat modeling lifecycle, Microsoft's STRIDE framework, and attack surface reduction.

📖 Lesson ID: MOD1-LES02
⏱️ Duration: 90 Minutes
🎯 Key Focus: Threat Actors, 6-Step Modeling, Microsoft STRIDE, Attack Surfaces
Figure 2.1: Penetration Testing and External Adversary Vector Mapping Source: Jinendar Kothari (Medium)

2.1 What is a Security Threat?

Any potential circumstance or event with the capacity to compromise operational integrity.

A security threat is any potential event, action, or circumstance that could harm an information system, compromise data, or disrupt services. Threats may originate from malicious human adversaries, software bugs, hardware failures, environmental hazards, or unintentional employee mistakes.

Common Types of Security Threats

🦠

1. Malware

Malicious software designed specifically to damage, disrupt, monitor, or gain unauthorized access to computer systems.

  • Viruses: Self-replicating code attached to valid files.
  • Worms: Autonomous self-propagating network infections.
  • Trojans: Disguised as legitimate utility software.
  • Spyware: Silently monitors keystrokes and credentials.
  • Ransomware: Encrypts storage and demands payoff.
🎣

2. Phishing

A social engineering vector where attackers pose as trusted institutions to deceive victims into handing over passwords or tokens.

Example: A student receives a counterfeit email spoofing the Registrar, asking them to verify their account on a lookalike login page.

💥

3. Denial-of-Service (DoS)

An attack intended to deplete server compute, bandwidth, or memory resources, causing services to become completely unavailable to legitimate traffic.

Availability Killer
🕵️

4. Insider Threats

Threats generated from inside the perimeter—such as disgruntled employees, instructors, contractors, or rogue administrators abuse valid credentials.

Example: A clerk dumps confidential transcripts onto a USB drive and leaks them online.

🎭

5. Social Engineering

Manipulating human psychological heuristics (urgency, authority, fear, vanity) to induce users into bypassing security controls.

Example: Attacker calls the campus IT helpdesk claiming to be the Dean demanding an emergency reset.

🔥

6. Physical Threats

Direct tangible hazards damaging computing facilities and transmission media.

  • Laptop and drive theft
  • Electrical fire and HVAC collapse
  • Flash flooding in server basements
  • Server room tailgating

2.2 What is Threat Modeling?

A structured engineering process of discovering, analyzing, and fixing threats before release.

🧠
The Core Philosophy of Threat Modeling

Threat modeling means thinking like an attacker so that we can better protect an information system. It shifts cybersecurity from reactive fire-fighting to proactive architectural hardening.

Before deploying an online Student Enrollment System, software architects must rigorously ask:

  • ❓ What sensitive assets and records does the system store?
  • ❓ Who has authorization to query or update this information?
  • ❓ Where are the entry points an adversary could enter through?
  • ❓ What catastrophic damage occurs if the database is exposed?
  • ❓ What defense-in-depth controls must be implemented now?
  • ❓ How will we detect and contain an active breach in progress?

2.3 Why is Threat Modeling Crucial?

🚀 Preemptive Detection: Identifies attack paths prior to production release.

🏛️ Architectural Clarity: Exposes fundamental flaws in system data flows.

🎯 Prioritized Spending: Directs limited IT budget to highest-impact vulnerabilities.

🛡️ Reduced Breaches: Greatly limits likelihood of damaging data exposures.

💼 Cost Efficiency: Fixing a security bug in design costs 10x less than post-breach.

📜 Compliance Alignment: Fulfills regulatory standards like ISO 27001 and NIST.

2.4 The 6-Step Threat Modeling Process

A systematic methodology applicable to any enterprise software or network environment.

Step 1

Identify Assets

Determine what critical resources need shielding: user credentials, student transcripts, database nodes, source code repos, and payment gateways.

Step 2

Identify Potential Threats

Brainstorm what adversaries or events could harm the target: unauthorized logins, malware delivery, DoS flood attacks, or insider leakage.

Step 3

Identify Vulnerabilities

Inspect flaws in software code, network configurations, or access rules: weak admin passwords, missing patches, cleartext HTTP, or open ports.

Step 4

Analyze Potential Impact

Forecast consequences if weaknesses are exploited: monetary loss, grade falsification, enrollment collapse, and reputational disaster.

Step 5

Select Security Controls

Implement appropriate safeguards: MFA, AES encryption, Web Application Firewalls (WAF), least privilege permissions, and automated backups.

Step 6

Review and Update Continuously

Threats evolve dynamically. Periodically repeat the analysis to audit software upgrades, new API integrations, and emerging CVE vectors.

2.5 The STRIDE Threat Modeling Framework

Developed by Microsoft, STRIDE categorizes all software threats into six distinct attack profiles.

Letter Threat Category Adversary Meaning University SIS Example Viable Security Control
S Spoofing Pretending to be someone else Attacker logs in using stolen teacher password MFA, Digital Certificates
T Tampering Unauthorized modification of data Hacker alters student graduation grade records Digital signatures, Cryptographic hashes
R Repudiation Denying an action without audit evidence Employee deletes records then claims innocence Write-once centralized audit logging
I Information Disclosure Exposing confidential data to unauthorized eyes Confidential scholarship files leaked publicly Data encryption (TLS 1.3, AES)
D Denial of Service Making a critical system unavailable Adversary floods enrollment server with traffic Rate limiting, DDoS scrubbing (Cloudflare)
E Elevation of Privilege Gaining higher access rights without authorization Student exploits bug to acquire Admin rights Principle of Least Privilege, RBAC checks
💬
Class Discussion: Which STRIDE category is the most dangerous?

There is no single correct answer! In a payment portal, Tampering or Information Disclosure might trigger direct financial and legal ruin. In a public enrollment rush, Denial of Service paralyzes business. For administrative control, Elevation of Privilege gives attackers keys to the kingdom. Students must evaluate based on asset value and operational impact.

2.6 Introduction to Attack Surfaces

The sum total of all vulnerable exposure points an adversary can attempt to probe.

An attack surface refers to all the reachable points through which an unauthorized user or threat actor can enter data into or extract data from an environment.

Common Attack Surface Vectors

  • 🌐 Public Web Forms & Login Portals: Vulnerable to brute force, credential stuffing, and SQL injection.
  • 🔌 APIs & Microservices: Broken object level authorization (BOLA) and unauthenticated endpoints.
  • 💾 Database Ports: MySQL/PostgreSQL ports exposed directly to public internet without VPN.
  • 🖥️ Open Network Ports: Unnecessary SSH (port 22) or SMB (port 445) exposed.
  • 👥 Employee Accounts: Over-privileged worker logins susceptible to social engineering.
  • 📦 Third-Party Libraries: Vulnerable NPM, Maven, or Python packages.

Attack Surface Reduction Strategies

  • ✂️ Disable Unnecessary Services: Turn off unused ports, daemons, and legacy APIs.
  • 🛡️ Network Segmentation: Isolate databases behind private subnets and reverse proxies.
  • 🔒 Zero Trust Architecture: Enforce explicit authentication and least privilege on every request.
  • 🧹 Credential Hygiene: Purge dormant student accounts and require immediate credential rotation.
  • 🔍 Regular Port Auditing: Execute Nmap vulnerability scans to catch inadvertent public listeners.

2.7 Lesson 2 Review & Discussion

1. Why is threat modeling described as "thinking like an attacker"? ➕
Because rather than merely checking software features, threat modeling analyzes systems through the motives, entry paths, tools, and goals of an adversary, revealing blind spots that developers typically overlook.
2. How does the STRIDE model help software developers build more resilient systems? ➕
STRIDE provides a standardized mental checklist. Developers can evaluate each data flow, process, and data store against the 6 specific threat types, ensuring no category (like Non-Repudiation or Elevation) is ignored during design.
3. What is an attack surface, and why is minimizing it a primary security objective? ➕
An attack surface is the total sum of entry points reachable by an attacker. Minimizing it reduces the number of opportunities and vulnerabilities an attacker can exploit, dramatically lowering the probability of intrusion.
