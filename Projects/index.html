Conducting a Basic Information Security Risk Assessment

Design and author a comprehensive executive risk assessment dossier for an enterprise digital system. Analyze business assets, threat actors, systemic vulnerabilities, CIA requirements, risk scores, and technical controls.

📋 Points: 20 Points
📁 Folder: /Projects
🎓 Deliverable: Formal Executive Risk Assessment Report

📝 Mandatory Report Structure (8 Sections)

Each submission must address all 8 technical sections in detail:

  • 1. System Description: Operational purpose, users, and tech architecture.
  • 2. Important Assets (Min 5): Critical hardware, software, data, and human assets.
  • 3. Potential Threats (Min 5): Specific malicious and non-malicious threat actors.
  • 4. Vulnerabilities (Min 5): Concrete software, network, human, or physical flaws.
  • 5. CIA Triad Analysis: How Confidentiality, Integrity, & Availability apply.
  • 6. Risk Assessment Matrix: At least 3 risks evaluated with \( L \times I \) scoring.
  • 7. Security Recommendations (Min 5): Actionable technical & admin controls.
  • 8. Executive Conclusion: Summary of why Information Assurance ensures survival.

Coursework Deliverable

Information Security Risk Assessment Report

Target System: University Student Enrollment System

Course: INFOSEC 101 (MWF 10:30am - 11:30am)
Term: College Semester Project
Status: Ready for Evaluation

1. System Description

The target system is an enterprise web application enabling users to authenticate, query records, process financial transactions, and maintain account state. It features a three-tier architecture: frontend web portal (Vue/React), microservice REST API gateway, and relational SQL database storage tier.

2. Important Assets Requiring Protection (Minimum 5)

  • Asset 1: Relational Database Records — Master database containing personal identities, passwords, and historical logs.
  • Asset 2: Financial Transaction Processing Engine — Billing and gateway ledger services executing real-time payments.
  • Asset 3: User Authentication Credentials — Password hashes, session tokens, and cryptographic private keys.
  • Asset 4: Web Application Server Fleet — Linux production servers running active customer-facing API microservices.
  • Asset 5: Administrative Master Accounts — High-privilege identity accounts capable of altering schema and rights.

3. Potential Threats (Minimum 5)

  • Threat 1: External Cybercrime Syndicates — Malicious actors attempting ransomware extortion and data exfiltration.
  • Threat 2: Credential Stuffing & Phishing Actors — Adversaries targeting staff with counterfeit authentication portals.
  • Threat 3: Distributed Denial of Service (DDoS) Botnets — High-volume volumetric flood attacks aimed at knocking services offline.
  • Threat 4: Malicious Insiders — Disgruntled employees or contractors attempting unauthorized record alteration or theft.
  • Threat 5: Environmental & Hardware Disruptions — Power grid collapse, server rack disk failure, and natural hazards.

4. Systemic Vulnerabilities (Minimum 5)

  • Vulnerability 1: Weak Default Password Policies — Allowing users to choose short, predictable passwords without MFA.
  • Vulnerability 2: Outdated Web Server Frameworks — Running older runtime versions containing known CVE vulnerabilities.
  • Vulnerability 3: Missing Database Network Segmentation — Direct database port exposure to public subnets.
  • Vulnerability 4: Lack of Automated Immutable Backups — No off-site snapshot backups configured for disaster recovery.
  • Vulnerability 5: Inadequate Employee Security Training — Staff lacking awareness to detect modern spear-phishing lures.

5. CIA Triad Analysis

• Confidentiality: Ensuring confidential user records, billing details, and personal transcripts can only be accessed by authorized identity holders through strict Role-Based Access Control and AES-256 encryption.

• Integrity: Preventing unauthorized modification, tampering, or deletion of ledger balances and official records through SHA-256 cryptographic hashing, database constraints, and immutable audit trails.

• Availability: Guaranteeing uninterrupted system accessibility for students, employees, and administrators through redundant load-balanced clusters, UPS power, and Cloudflare DDoS filtering.

6. Risk Assessment Matrix & Scoring

Identified Risk Scenario Likelihood (1–5) Impact (1–5) Risk Score (\( L \times I \)) Priority Level
Ransomware encryption of core database 3 (Possible) 5 (Catastrophic) 15 / 25 High / Critical
Admin account takeover via weak credentials 4 (Likely) 5 (Catastrophic) 20 / 25 Critical Priority
Portal DDoS outage during registration 4 (Likely) 4 (Severe) 16 / 25 High Priority

7. Actionable Security Recommendations (Minimum 5 Controls)

  1. Control 1 (Technical): Mandate Multi-Factor Authentication (MFA) with FIDO2 or TOTP for all administrator and user logins.
  2. Control 2 (Technical): Enforce TLS 1.3 for all web traffic and AES-256 encryption at rest for database data storage volumes.
  3. Control 3 (Technical): Configure automated daily 3-2-1 immutable cloud backups with monthly disaster recovery dry-runs.
  4. Control 4 (Administrative): Formulate and enforce an institutional Information Security Policy and annual security awareness training.
  5. Control 5 (Physical): Restrict server room facility entry using biometric readers, dual-signoff logs, and CCTV surveillance.

8. Executive Conclusion

Information Assurance is not a superficial software plug-in; it is the vital foundation sustaining modern organizational operations. By systematically categorizing assets, evaluating threats with STRIDE, remediating system vulnerabilities, and enforcing defense-in-depth controls, our institution guarantees the ongoing confidentiality, integrity, and availability of its vital digital mission.
