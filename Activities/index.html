📖 Background Dossier: University Student Enrollment System

A metropolitan university develops an online Student Enrollment System that enables 25,000 students to register for academic subjects, view official grades, submit tuition payments, and update personal identifying information.

System User Roles:

👤 Students

Permitted to access personal profiles, enrollment schedules, and individual transcripts.

👨‍🏫 Faculty / Teachers

Authorized to manage grading sheets and class lists for their officially assigned sections.

🔑 Administrators

Empowered to manage accounts, matriculation statuses, database setups, and system configs.

🚨
Audit Discovery: 6 Critical Security Deficiencies
  1. Weak Passwords: Students are permitted to set trivial numeric passwords like 12345678.
  2. Misconfigured Database: The MySQL database port is openly reachable without encryption or IP filtering.
  3. Broken Object Level Authorization: Students can view other students' records simply by modifying the student ID query parameter in the URL.
  4. Zero Redundancy: There are no regular or automated off-site database backups.
  5. Severe Server Crashes: The web portal frequently crashes during registration peak traffic windows.
  6. Shared Administrative Credentials: Administrators use a single shared root account without individual logins or MFA.

Activity 1: Identify the CIA Triad

Select which CIA principle (Confidentiality, Integrity, or Availability) is primarily compromised in each situation.

1. Students can view other students' private information by altering the URL ID parameter.
2. An unauthorized user modifies official student grade records in the database.
3. The enrollment website becomes completely unresponsive during registration rush hours.
4. An external cyber attacker successfully steals administrator login credentials.
5. Tuition payment ledger records are secretly modified without bank authorization.

Strategic IT Takeaway

Because Weak administrator passwords scores 20/25, the university IT steering committee must prioritize multi-factor authentication, account individualization, and password complexity before any other software enhancements.

Activity 4: Recommend Appropriate Security Controls

Match institutional vulnerabilities with robust, industry-standard mitigation safeguards.

1. Weak Passwords

Recommended Control:

✅ Enforce minimum 12-character complex password policy, rate-limiting on login attempts, and mandatory Multi-Factor Authentication (MFA).

2. Unauthorized Record Access (IDOR)

Recommended Control:

✅ Implement server-side Role-Based Access Control (RBAC) validation verifying session tokens against requested student record IDs on every query.

3. No Database Backups

Recommended Control:

✅ Automate daily 3-2-1 backup strategy (3 copies, 2 different media types, 1 immutable off-site/cloud snapshot) with weekly restoration tests.

4. Unencrypted Sensitive Data

Recommended Control:

✅ Mandate TLS 1.3 encryption in transit for all web endpoints and AES-256 transparent data encryption (TDE) for database volumes at rest.

5. Website Downtime During Enrollment

Recommended Control:

✅ Deploy elastic cloud auto-scaling, reverse-proxy load balancers (NGINX), and Cloudflare DDoS protection & CDN caching.

6. Shared Administrator Accounts

Recommended Control:

✅ Abolish shared logins. Issue distinct individual administrative accounts with hardware FIDO2 MFA tokens and immutable SIEM audit trails.
