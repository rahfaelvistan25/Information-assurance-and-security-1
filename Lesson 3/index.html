LESSON 3: Vulnerabilities and Security Weaknesses

Investigate internal flaws across software, hardware, networks, humans, and system configurations. Learn the triad of Administrative, Technical, and Physical controls, Principle of Least Privilege (PoLP), and the CVSS scoring framework.

📖 Lesson ID: MOD1-LES03
⏱️ Duration: 90 Minutes
🎯 Key Focus: Vulnerability Types, Burglar Analogy, PoLP, CVSS v3.1
Figure 3.1: Automated Vulnerability Scanner Audit Pipeline Source: TryHackMe / Farrosfr

3.1 What is a Vulnerability?

The inherent flaw that transforms a dormant threat into a live compromise.

A vulnerability is a weakness or flaw in a computer system, network architecture, application source code, configuration parameter, or organizational procedure that could be exploited by a threat actor.

🔍
The Real-World Password Example

A university enrollment website allows students to configure simple 8-digit numeric passwords such as 12345678. An attacker uses automated dictionary tools to crack the accounts.
• Vulnerability: The weak password policy allowing predictable passwords.
• Threat Actor: The external cyber attacker executing dictionary tools.
• Risk / Impact: Mass unauthorized access to confidential student records.

3.2 The Five Major Types of Vulnerabilities

Weaknesses exist across multiple technical and human organizational layers.

Category A

💻 Software Vulnerabilities

Flaws embedded inside operating systems, microservice application code, or third-party dependencies.

  • SQL Injection (SQLi): Unsanitized input allowing database takeover.
  • Cross-Site Scripting (XSS): Malicious JavaScript executed in user browsers.
  • Buffer Overflows: Memory corruption granting code execution.
  • Unpatched Software: Running legacy server versions with publicly published CVEs.
Category B

🌐 Network Vulnerabilities

Defects in network topologies, routing protocols, and perimeter configurations.

  • Unsecured Wi-Fi: Campus public wireless with no WPA3 encryption.
  • Open Unused Ports: Leaving port 21 (FTP) or 23 (Telnet) open.
  • Lack of Segmentation: Flat networks where student Wi-Fi directly talks to finance DB.
  • Cleartext Protocols: Transmitting passwords over HTTP instead of HTTPS.
Category C

🧑‍💼 Human Vulnerabilities

Weaknesses stemming from psychological manipulation, negligence, and lack of security training.

  • Password Sharing: Administrators sharing one "admin" password across teams.
  • Phishing Susceptibility: Employees clicking malicious macro-enabled Excel sheets.
  • Credential Reuse: Reusing the same password on social media and school servers.
  • Accidental Leakage: Misaddressing sensitive emails with BCC instead of CC.
Category D

🏢 Physical Vulnerabilities

Failures in tangible perimeter barriers, environmental controls, and facility surveillance.

  • Unlocked Server Rooms: Unrestricted physical access to blade racks.
  • Unattended Laptops: Workstations left unlocked in public campus libraries.
  • No Backup Generators: Outages causing immediate server crashes and disk corruption.
  • Missing CCTV: Blind spots around server room entry doors.
Category E

⚙️ Configuration Vulnerabilities

Security exposures caused by incorrect administrative setup rather than flawed code.

Public Cloud Buckets: S3 buckets or Google Drive folders accidentally shared with "Anyone with link".
Default Credentials: Leaving routers with username admin and password admin.
Excessive Permissions: Granting root/DBA privileges to basic web application accounts.

3.3 Threat vs. Vulnerability vs. Risk

Mastering the fundamental terminology distinctions.

🏠
The Master House Analogy
1. Threat: The Burglar

An external entity with the capability and intent to cause harm.

2. Vulnerability: Unlocked Door

An inherent weakness or opening that permits entry.

3. Risk: Stolen Valuables

The actual probability and impact of the burglar entering and stealing possessions.

Term Formal Academic Definition Analogy Entity IT Information System Example
Threat Something that could cause intentional or accidental harm. A burglar scouting a neighborhood A black-hat hacker searching for targets
Vulnerability An internal weakness or flaw that can be exploited. An unlocked front door or window latch A weak administrator password (e.g. "admin123")
Risk The possibility and severity of damage occurring. Possibility of electronics being stolen Possibility of student records exfiltration & fines

3.5 What is a Security Control?

Safeguards, countermeasures, and mechanisms designed to reduce risk.

Category 1

📜 Administrative Controls

Managerial policies, governance standards, guidelines, operational procedures, and employee handbooks.

  • Acceptable Use Policies (AUP)
  • Password expiration rules
  • Employee background screening
  • Security awareness workshops
  • Incident response playbooks
Category 2

💻 Technical Controls

Hardware and software countermeasures implemented directly into computing networks and applications.

  • Next-Gen Firewalls (NGFW)
  • Intrusion Detection Systems (IDS/IPS)
  • End-to-End Encryption (AES, TLS)
  • Multi-Factor Authentication (MFA)
  • Antivirus and EDR agents
Category 3

🏢 Physical Controls

Tangible real-world measures shielding buildings, datacenters, server racks, and cables from direct contact.

  • Biometric badge scanners & locks
  • Security guards and sign-in logs
  • CCTV recording systems
  • Fire suppression gas systems (FM-200)
  • Server rack lockboxes

3.6 The Principle of Least Privilege (PoLP)

Granting users and processes solely the minimal privileges required to perform assigned tasks.

The Principle of Least Privilege (PoLP) dictates that any entity—user, application, process, or script—must be granted only the minimum permissions essential to its legitimate function, and for no longer than needed.

Role in University SIS Legitimate Appropriate Access Prohibited / Restricted Access
Student View personal class schedule, bill, and personal grades Cannot edit grades, view other students, or access servers
Teacher Enter and update grades for assigned course sections Cannot view student financial debt or modify server configs
Registrar Manage course registration statuses and verify degrees Cannot directly change backend database schemas
System Administrator Manage web servers, patch OS, and configure user permissions Audited strictly through dual-control and session logs
🛡️
Why PoLP is Mandatory

If an attacker compromises a student account, PoLP ensures the attacker cannot compromise the entire university database or modify other accounts. It constrains the blast radius of any single credential breach.

3.7 Vulnerability Management Lifecycle & CVSS

A continuous 7-step hygiene process and industry-standard severity scoring.

The 7-Step Lifecycle

  1. Discover Assets: Catalog every server, laptop, and API endpoint.
  2. Scan for Vulnerabilities: Run tools like Nessus, OpenVAS, or Trivy.
  3. Evaluate Findings: Discard false positives and confirm real exposure.
  4. Prioritize Risk: Rank by CVSS severity and business criticality.
  5. Apply Patches / Fixes: Update firmware, recompile code, adjust configs.
  6. Verify & Rescan: Test systems to ensure the flaw is remediated.
  7. Continuous Monitoring: Re-audit regularly as new exploits emerge.

Common Vulnerability Scoring System (CVSS)

CVSS is an open framework ranging from 0.0 to 10.0 to quantify the technical severity of software vulnerabilities.

CVSS Score Severity Tier Urgency of Action
0.0 None Informational only
0.1 – 3.9 Low Scheduled maintenance cycle
4.0 – 6.9 Medium Patch within normal 30-day window
7.0 – 8.9 High Expedited patch within 7 days
9.0 – 10.0 Critical Emergency patch within 24 hours

3.9 Lesson 3 Review & Discussion

1. What is the fundamental difference between a threat and a vulnerability? ➕
A threat is an external force or potential source of harm (like a hacker or hurricane). A vulnerability is an internal flaw or weakness in our own systems (like an unpatched library or weak password) that allows a threat to succeed.
2. Why are weak passwords considered security vulnerabilities? ➕
Because weak passwords can be guessed or brute-forced in milliseconds using automated dictionaries, providing attackers with immediate unauthorized access without needing complex exploits.
3. What are the three major categories of security controls? ➕
Administrative (policies, training, procedures), Technical (firewalls, encryption, MFA, software settings), and Physical (locks, guards, CCTV, biometrics, fire suppression).
4. Why should students never have administrator access to a university database? ➕
According to the Principle of Least Privilege, students only need to view their personal academic records. Granting administrator access violates this principle, creating severe risk of grade tampering, tuition debt wiping, or privacy leaks.
5. Why is vulnerability management a continuous process rather than a one-time project? ➕
Software changes constantly through updates and new features, while security researchers and adversaries discover thousands of new Common Vulnerabilities and Exposures (CVEs) every single month. A secure system today can become vulnerable tomorrow.
6. What is the primary purpose of CVSS? ➕
To provide an objective, standardized numeric score (0.0 to 10.0) reflecting the technical severity of software vulnerabilities, helping security teams prioritize which vulnerabilities must be patched first.
